# UC-26: 収納成立を手段別成立条件で検知する

- **事前条件**: 業務状態が「収納依頼中」で、収納手段ごとの成立条件(口座振替=引落確定、カード=売上確定、振込=入金消込、コンビニ=収納消込、現金=受領確認)が定まっている
- **事後条件**: 手段別の成立条件の充足が検知され、業務状態が「収納成立」となって契約成立条件の一方を充足した情報が契約成立(計上)へ引き渡される。成立が検知できない場合は収納不能として収束処理へ回し、検知遅延は滞留として業務監視の対象にする

```mermaid
sequenceDiagram
    autonumber
    actor act4 as 新契約事務担当者<br/>ACT-4
    participant sys as 個人保険新契約システム
    participant ext9 as 決済サービス<br/>EXT-9

    act4->>sys: 収納状況一覧画面で対象案件を選び<br/>「収納結果を確認」ボタンをクリック
    activate sys

    opt FUNC-26: 収納成立検知機能
        sys->>ext9: 処理識別を渡して収納結果<br/>(手段別の成立可否・成立日時)を照会
        activate ext9
        ext9-->>sys: 収納結果(成立/不成立/処理中)
        deactivate ext9

        break 成立条件が未充足(不成立)
            sys->>sys: 業務状態を「収納不能」へ更新し、<br/>不成立の事由と検知日時を記録
            sys-->>act4: 収納状況詳細画面に不成立である旨と、<br/>再依頼・代替手段提示へ進む導線を表示
            Note over sys: 参照: UC-28 収納不成立を再依頼・<br/>代替手段提示で収束させる
        end

        break 結果が処理中・照会不達で検知が遅延
            sys->>sys: 業務状態を「収納依頼中」のまま保持し、<br/>検知遅延として滞留日数と次回確認予定を記録
            sys-->>act4: 収納状況詳細画面に検知待ちである旨と、<br/>滞留日数・次回確認予定を表示
        end

        sys->>sys: 業務状態を「収納成立」へ更新し、成立日時・<br/>成立を判定した手段別条件・処理識別を記録して<br/>契約成立(計上)へ収納成立を引き渡し
        sys-->>act4: 収納状況詳細画面に収納成立である旨と、<br/>責任開始日の確定へ進む導線を表示
        Note over sys: 参照: UC-68 業務通知を配信する
    end

    deactivate sys
```
