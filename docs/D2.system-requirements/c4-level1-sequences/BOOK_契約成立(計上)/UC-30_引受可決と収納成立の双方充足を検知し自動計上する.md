# UC-30: 引受可決と収納成立の双方充足を検知し自動計上する

- **事前条件**: 申込が査定・収納の対象となり、業務状態が「成立条件待ち」。引受可決と第一回保険料収納成立は到着順を問わない
- **事後条件**: 引受可決と収納成立の双方の充足が検知されて契約成立日が一意に確定し、業務状態が「計上処理中」となって計上処理が自動起動する。一方のみ充足の場合は成立条件待ちのまま滞留管理し、謝絶・収納未了撤回の場合は「不成立」として計上しない

```mermaid
sequenceDiagram
    autonumber
    actor act4 as 新契約事務担当者<br/>ACT-4
    participant sys as 個人保険新契約システム

    act4->>sys: 成立条件待ち一覧画面で対象契約を選び<br/>「成立条件を確認」ボタンをクリック
    activate sys

    opt FUNC-30: 計上起動(双方充足検知)機能
        sys->>sys: 引受査定の判定結果と第一回保険料の収納結果を<br/>到着順を問わず突合し、契約成立条件の<br/>充足状況を判定

        break 謝絶・収納未了撤回・申込撤回のいずれかが確定
            sys->>sys: 業務状態を「不成立」へ更新し、<br/>不成立の事由と判定日時を記録して計上しない
            sys-->>act4: 成立条件詳細画面に契約不成立である旨と、<br/>不成立事由を表示
        end

        break 一方のみ充足で他方が未到着
            sys->>sys: 業務状態を「成立条件待ち」のまま保持し、<br/>未到着側の工程と滞留日数を記録
            sys-->>act4: 成立条件詳細画面に他方の充足待ちである旨と、<br/>未到着側の工程・滞留日数を表示
            Note over sys: 参照: UC-33 計上滞留を滞留管理し<br/>業務時間内に処理する
        end

        sys->>sys: 双方充足の時点から社内規程に基づき<br/>契約成立日を一意に確定し、<br/>責任開始日とは別概念として保持
        sys->>sys: 業務状態を「計上処理中」へ更新し、<br/>計上処理を人手を介さず自動起動
        sys-->>act4: 成立条件詳細画面に契約成立日と、<br/>計上処理を開始した旨を表示
    end

    deactivate sys
```
