# D3: C4モデル レベル2(コンテナ)

## 遵守すべき重要ルール

1. **レベル1 を変えない**: 人(`ACT-*`)・外部システム(`EXT-*`)・対象システムの境界はレベル1 に従う。過不足があれば本書で辻褄を合わせず、レベル1 の見直し要否をユーザーに確認する。
2. **未決で残さない**: コンテナの分割・技術・連携方式は、ADR に決定があればそれに従い、なければレベル1 シーケンスから設計して埋める。ADR に基づかない箇所には要確認マーカーを付す。
3. **ID を振り直さない**: `CNT-*` はレベル2 シーケンスのライフラインから参照される。採番済みの ID は変えず、欠番も再利用しない。

## 処理

### 1. 分岐する

- もしレベル1 またはレベル1 シーケンスが存在しないなら、先に作成が必要な旨を伝えて終了する。
- そうでなく、`docs/D3.system-design/c4-level2-container.md` が存在しないなら、§2(新規作成)に進む。
- それ以外なら、§3(更新)に進む。

### 2. 新規作成

#### 2.1 上流を読む

レベル1 シーケンスを読み、UC ごとに、操作する人・外部とのやり取り・記録対象・利用者の操作を起点としない処理を控える。もし ADR が存在するなら、承認済みの決定だけを採用する。

#### 2.2 コンテナを設計する

コンテナは独立して実行・デプロイされる単位とし、ドメインや機能をそのままコンテナにしない。業務処理は 1 つを出発点とし、以下に当たる場合だけ分ける。

- 社外の人が自ら操作する UC があれば、社外向けの利用者向けアプリケーションを分ける
- 実行特性や利用者層が他と異なるドメイン群があれば、業務処理から切り出す
- 利用者の操作を起点としない処理があれば、非同期処理・バッチを分ける
- 保持期間・改ざん防止・格納形式が異なる記録対象があれば、データストアを分ける

いずれのコンテナにも割り当たらない UC・人・外部システムが残るなら、分割を見直す。

#### 2.3 技術と連携方式を決める

- もし ADR に決定があるなら、それに従う。そうでないなら、AWS のサービスを前提に、コンテナの特性に合うものを 1 つ選ぶ(候補を併記しない)。AWS に適するサービスが無い場合だけ AWS 以外を選ぶ。実行基盤・言語は理由なくコンテナごとに変えない。
- 線は呼び出す側から呼び出される側へ引き、同じ組のやり取りは 1 本にまとめる。応答を待つなら同期、待たないなら非同期とし、方式を添える。

#### 2.4 図と表を埋める

- 図は `flowchart LR` で描く(C4 専用記法は使わない)。人・外部システムの `subgraph` はレベル1 と同じ括りにする。
- `CNT-*` は図の上から順に 1 から振る。
- 設計根拠列には、ADR に基づくなら ADR の ID、そうでないなら分割・選定の根拠にした UC と特性を書く。
- `sidebars.ts` の「D3. システム設計」カテゴリに登録する。

### 3. 更新

- 上流(レベル1・レベル1 シーケンス・ADR)で変わった箇所に関わるコンテナと関係だけを §2 の手順で見直す。
- 新しいコンテナには全体の最大値の次の ID を振る。不要になったコンテナは行を削除し、ID を欠番にする。
- もしコンテナの分割・統合で既存 ID の引き継ぎ先が決まらないなら、ユーザーに確認する。

## 完成時のセルフチェック

- 図の `ACT-*` / `EXT-*` の集合が、レベル1 §登場要素の集合と一致している
- レベル1 シーケンスの全 `UC-*` が、コンテナ表の関連 UC 列に現れている
- 図のノード・線が、コンテナ表・関係表の行と過不足なく対応している
- ADR に基づかない技術・連携方式に要確認マーカーが付いている
- `CNT-*` に重複が無く、更新時は既存の ID とコンテナの対応が変わっていない
- `{{` が残っていない
